# API Specification Refinement Benchmark

This repository contains a collection of REST API implementations together with their corresponding OpenAPI specifications. It is intended to support the replication of experiments involving **REFINE**, an automated specification-refinement approach that improves OpenAPI specifications by analyzing API implementations.

Each project contains:

- the original OpenAPI specification;
- the API implementation source code;
- the enhanced specification generated by REFINE;
- a discrepancy report describing differences between the original specification and the implementation;
- token usage and cost information collected during the refinement process.

## Repository Structure

Each API follows the same organization:

```text
<api-name>/
├── pom.xml
├── pom-fat-jar.xml
├── specification
│   ├── original
│   │   └── <api>_original.json
│   └── enhanced
│       ├── <api>_enhanced.json
│       ├── <api>_original_discrepancy_<timestamp>.md
│       └── token_usage_<timestamp>.csv
└── src/
    └── ...
```

The repository currently includes the following case studies:

- `features-service`
- `restcountries`
- `rest-ncs`
- `rest-scs`

## Specification Artifacts

### Original Specification

Located in:

```text
specification/original/
```

This directory contains the original OpenAPI specification provided with the API project. These specifications constitute the baseline documentation before refinement.

Example:

```text
specification/original/rest-ncs_original.json
```

---

### Enhanced Specification

Located in:

```text
specification/enhanced/
```

REFINE generates an enhanced OpenAPI specification by comparing the original specification against the API implementation.

The refinement process may include improvements such as:

- correcting response status codes;
- updating parameter requirements;
- adding request and response examples;
- enriching parameter examples;
- documenting implementation-observed behavior;
- improving the overall completeness of the specification.

The enhanced specification preserves the original API semantics while making the documentation more faithful to the actual implementation.

Example:

```text
specification/enhanced/rest-ncs_enhanced.json
```

## Discrepancy Report

For every enhanced specification, REFINE produces a discrepancy report:

```text
<api>_original_discrepancy_<timestamp>.md
```

The report compares the original specification against the implementation and identifies inconsistencies, including:

- endpoints missing from the specification;
- endpoints missing from the implementation;
- parameter mismatches;
- response code mismatches;
- other implementation-specification divergences.

Each discrepancy is reported along with the affected endpoint and a description of the detected inconsistency, enabling researchers to understand why modifications were introduced to the enhanced specification.

## Token Usage

REFINE records the language model resource consumption in

```text
token_usage_<timestamp>.csv
```

This file contains the token usage and associated execution cost for the refinement process, enabling reproducibility and cost analysis across experiments.

Typical recorded information includes:

- input tokens;
- output tokens;
- total tokens;
- estimated execution cost;
- execution metadata.

## Source Code

The `src/` directory contains the complete API implementation used as the ground truth during refinement.

REFINE analyzes the implementation alongside the original specification to identify missing or inconsistent documentation elements and produce an enhanced specification.

## Experimental Workflow

For each API project, the experimental pipeline consists of the following steps:

1. Start from the original OpenAPI specification.
2. Analyze the API implementation source code.
3. Execute REFINE.
4. Generate:
   - an enhanced OpenAPI specification;
   - a discrepancy report comparing the original specification with the implementation;
   - a token usage report documenting computational cost.

The enhanced specification can then be compared with the original specification to evaluate the improvements introduced by the refinement process.

## Purpose

This repository serves as a benchmark for evaluating automated techniques for refining OpenAPI specifications. It provides all artifacts required for replication:

- original API specifications;
- implementation source code;
- refined specifications;
- discrepancy reports;
- token usage and cost measurements.
